### C — уровень 0
**Почему отдельный уровень.** Сам Swift переносится (Linux, Windows, Android SDK), и механизм уровня 2 вместе с ним. Не переносятся уровень 1 и смысл уровня 2: вне Apple платформенный API написан на C (libc, POSIX, Android NDK) или на Java, и Swift-мосту там звать почти нечего. C — единственный хостовый язык, на котором платформенный API есть везде, включая Apple: CoreFoundation, CoreGraphics, libdispatch, Accelerate, Security, `UIApplicationMain`. Спрос записан до проектирования: первый экран на iOS упёрся не в Swift-only символы, а в шесть констант из заголовков, одну экспортированную `const` и одну C-функцию (NOTES «iOS»).

**Вызов динамический — в отличие от Swift.** C ABI вызывается по сигнатуре, известной в рантайме, — ровно то, чего нет у Swift (§5 «Главное разделение: данные vs вызовы»). Поэтому оба режима полны, а не равны в ограничении:
- Компилятор — прямой вызов из сгенерированного C: `#include` заголовка, unboxed-аргументы, типы из заголовка. Нужен только источник деклараций.
- Интерпретатор — `dlsym` и диспетчер уровня 1, обобщённый на любой указатель на функцию. Прототипы `objc_msgSend` и есть приведения указателя на функцию; для C тот же набор с другим указателем, а `id`/`SEL` становятся обычными целочисленными слотами (восемь вместо шести). Классификация структур по AAPCS64, трамплины, список отказов — те же (NOTES «ObjC bridge»). Генерации и `dlopen` нет, поэтому на устройстве dev client достаёт любую экспортированную функцию системных библиотек без пересборки — больше, чем Swift-only символы, которым нужны слинкованные стабы (§3 «Dev client (паттерн Expo)»).
- Вариадические функции (`printf`, `CFStringCreateWithFormat`) — отказ: на arm64 у Apple вариадические аргументы идут на стеке, фиксированный прототип их не кладёт. Отдельная форма вызова — по триггеру.

**Декларации — из заголовка, clang'ом.** Источник сигнатур — сам заголовок, разобранный clang'ом (`-ast-dump=json` или libclang), аналог symbol graph у генератора стабов. Не Swift-импорт тех же заголовков: он переименовывает и перетипизирует (`CGFloat`, optionals, `NS_ENUM` как struct с боксом — NOTES «iOS»). Из заголовка:
- функции → вары с сигнатурой, факт `:host-call` (§5 «Объявленная граница, REPL, доставка стабов»);
- структуры → `deflayout` с именами полей (§4 «Низкоуровневый слой: числа, layout, память»);
- `enum`, `NS_ENUM`/`NS_OPTIONS`, целочисленные `#define` → константы времени разбора, значением;
- `extern const` и глобалы → чтение через `dlsym` в интерпретаторе, прямое обращение в компиляторе.

Объявление в `ns` — по образцу `require-swift`, имя формы не выбрано. Разбор кэшируется по содержимому (заголовок, SDK, флаги) в общем хранилище (§3 «Кэш: общее хранилище по содержимому, тонкий каталог в проекте»), как Swift-стабы. Неразобранное — в отчёт с причиной, как у генератора (§5 «Генератор стабов»): отказ — это «Unable to resolve», а не тихо неправильный вызов.

**Только в заголовке.** Части C в бинаре нет: `static inline` функции (`CGRectMake` — `CG_INLINE`), функциональные макросы, значения `enum`. Константы снимаются значением при разборе — `dlsym` им не нужен. `static inline` компилятор просто вызывает через `#include`; интерпретатору нужен тонкий C-стаб — на Маке через clang и `dlopen`, тот же путь, что у скомпилированных юнитов, на устройстве — слинкованный в dev client. До триггера — отказ в отчёте. Функциональные макросы — отказ.

**Встреча с уровнем 1.** Константа из заголовка — число, а не бокс, и уровень 1 принимает его там, где селектор ждёт `NSUInteger`. Зазор из NOTES «iOS» (стаб даёт `UIControl.Event` боксом, а `sendActionsForControlEvents:` ждёт число) закрывается без встречи уровней на месте вызова. Имена полей структур тоже приходят отсюда: type encoding их не даёт, поэтому уровень 1 держит встроенную таблицу (`CGRect`, `UIEdgeInsets`…) — с заголовком она становится запасной.

**Владение.** Новых видов значений не нужно: `ptr`, `view`, арены и три вида владения — §4 «Низкоуровневый слой: числа, layout, память».
- `char *` в аргументе — копия строки на время вызова; в возврате — копия в строку, указатель не наш, если заголовок не говорит иного.
- CF-объекты — по аннотациям `CF_RETURNS_RETAINED`/`CF_RETURNS_NOT_RETAINED`, которые clang видит в AST, иначе по правилу Create/Copy против Get из имени функции, как у ARC. Объект держит RC, `CFRelease` — в деструкторе; toll-free bridged типы отдаются уровню 1 как `id`.
- Ошибка через код возврата или `errno` — не исключение моста; превращать её в `ex-info` — дело биндинга.

**Вызов внутрь.** Колбэк с `void *context` (`qsort_r`, `dispatch_async_f`, CF-наблюдатели) несёт Clojure-fn в контексте и садится на трамплины по форме возврата уровня 1; тело исполняется под `host_depth` и не паркуется (§5 «Вызов внутрь: делегат не паркуется»). Голый указатель на функцию без контекста требует своей точки входа на замыкание; без JIT на iOS это заранее собранный пул трамплинов, как у libffi closures на iOS, — по триггеру. Колбэки реального времени (аудио render) — отказ: там нельзя аллоцировать и трогать RC, это работа хоста.

**Переносимость.** Классификация аргументов — по архитектуре (AAPCS64 против SysV x86_64), и на x86_64 действует тот же список отказов, что у уровня 1; при реализации это строка в `docs/portability.md`. На Linux и Android уровень тот же, меняются только заголовки SDK.

**Порядок.** Первый срез — декларации и константы: закрывает числа, которые экран пишет руками. Второй — вызов функций: `UIApplicationMain` уходит из `main.c`. Стабы для `static inline` и колбэки без контекста — по триггеру. Статус — §10, шаг 8b.
