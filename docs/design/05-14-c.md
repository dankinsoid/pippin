### C — уровень 0
**Почему отдельный уровень.** Сам Swift переносится (Linux, Windows, Android SDK), и механизм уровня 2 вместе с ним. Не переносятся уровень 1 и смысл уровня 2: вне Apple платформенный API написан на C (libc, POSIX, Android NDK) или на Java, и Swift-мосту там звать почти нечего. C — единственный хостовый язык, на котором платформенный API есть везде, включая Apple: CoreFoundation, CoreGraphics, libdispatch, Accelerate, Security, `UIApplicationMain`. Спрос записан до проектирования: первый экран на iOS упёрся не в Swift-only символы, а в шесть констант из заголовков, одну экспортированную `const` и одну C-функцию (NOTES «iOS»).

**Вызов динамический — в отличие от Swift.** C ABI вызывается по сигнатуре, известной в рантайме, — ровно то, чего нет у Swift (§5 «Главное разделение: данные vs вызовы»). Поэтому оба режима полны, а не равны в ограничении:
- Компилятор — прямой вызов из сгенерированного C: `#include` заголовка, unboxed-аргументы, типы из заголовка. Нужен только источник деклараций.
- Интерпретатор — `dlsym` и диспетчер уровня 1, обобщённый на любой указатель на функцию. Прототипы `objc_msgSend` и есть приведения указателя на функцию; для C тот же набор с другим указателем, а `id`/`SEL` становятся обычными целочисленными слотами (восемь вместо шести). Классификация структур по AAPCS64, трамплины, список отказов — те же (NOTES «ObjC bridge»). Генерации и `dlopen` нет, поэтому на устройстве dev client достаёт любую экспортированную функцию системных библиотек без пересборки — больше, чем Swift-only символы, которым нужны слинкованные стабы (§3 «Dev client (паттерн Expo)»).
- Вариадические функции (`printf`, `CFStringCreateWithFormat`) — отказ: на arm64 у Apple вариадические аргументы идут на стеке, фиксированный прототип их не кладёт. Отдельная форма вызова — по триггеру.

**Декларации — из заголовка, clang'ом.** Источник сигнатур — сам заголовок, разобранный clang'ом (`-ast-dump=json` или libclang), аналог symbol graph у генератора стабов. Не Swift-импорт тех же заголовков: он переименовывает и перетипизирует (`CGFloat`, optionals, `NS_ENUM` как struct с боксом — NOTES «iOS»). Из заголовка:
- функции → вары с сигнатурой, факт `:host-call` (§5 «Объявленная граница, REPL, доставка стабов»);
- структуры → `deflayout` с именами полей (§4 «Низкоуровневый слой: числа, layout, память»);
- `enum`, `NS_ENUM`/`NS_OPTIONS`, целочисленные `#define` → константы времени разбора, значением;
- `extern const` скаляр и `const` указатель → чтение через `dlsym` один раз при загрузке; **мутабельный глобал — отказ**: снимок значения в варе перестаёт быть значением глобала, а чтение на каждое обращение — это уже не константа, а своя форма вара (поправка первого среза: `NSFoundationVersionNumber` и `kCFCoreFoundationVersionNumber` объявлены без `const` именно так).

Объявление в `ns` — **`(:require-c [UIKit :refer [...]])`**, по образцу `require-swift`: имя парное к нему и называет уровень, а не механизм (clang, заголовок, AST), который сменится; скан `ns`-форм остаётся одним сканом на ещё один ключ. Опции те же — `:as`, `:refer` — плюс `:header "math.h"` для заголовка, который не зонтик фреймворка; модуль — пространство имён своего имени.

**Имена — как в заголовке, без kebab.** `UIControlEventTouchUpInside`, а не `ui-control-event-touch-up-inside`. Kebab у уровней 1 и 2 переводит имя, которое хост сам построил из слов (селектор, базовое имя Swift-функции), и перевод обратим. Имя C-константы — не слова, а один идентификатор, которым она записана в заголовке, в документации Apple и в любом ответе на вопрос о ней; перевод был бы выдуманным именем и необратим (`NSTextAlignmentCenter` → `ns-text-alignment-center` → `NS`? `Ns`?). Прецедент рядом: имя класса уровень 1 тоже берёт как есть — `(objc-class "UIScreen")`.

Разбор кэшируется по содержимому в общем хранилище (§3 «Кэш: общее хранилище по содержимому, тонкий каталог в проекте»), как Swift-стабы. Ключ — модуль, заголовок, триплет, SDK, флаги, список имён и версия clang'а и генератора; попадание проверяется по `stat` каждого заголовка, который clang прочитал (`-MD`), поэтому правка в SDK промахивается. Неразобранное — в отчёт с причиной, как у генератора (§5 «Генератор стабов»): отказ — это «Unable to resolve», а не тихо неправильный вызов.

**Только в заголовке.** Части C в бинаре нет: `static inline` функции (`CGRectMake` — `CG_INLINE`), функциональные макросы, значения `enum`. Константы снимаются значением при разборе — `dlsym` им не нужен. `static inline` компилятор просто вызывает через `#include`; интерпретатору нужен тонкий C-стаб — на Маке через clang и `dlopen`, тот же путь, что у скомпилированных юнитов, на устройстве — слинкованный в dev client. До триггера — отказ в отчёте. Функциональные макросы — отказ.

**Встреча с уровнем 1.** Константа из заголовка — число, а не бокс, и уровень 1 принимает его там, где селектор ждёт `NSUInteger`. Зазор из NOTES «iOS» (стаб даёт `UIControl.Event` боксом, а `sendActionsForControlEvents:` ждёт число) закрывается без встречи уровней на месте вызова. Имена полей структур тоже приходят отсюда: type encoding их не даёт, поэтому уровень 1 держит встроенную таблицу (`CGRect`, `UIEdgeInsets`…) — с заголовком она становится запасной.

**Владение.** Новых видов значений не нужно: `ptr`, `view`, арены и три вида владения — §4 «Низкоуровневый слой: числа, layout, память».
- `char *` в аргументе — копия строки на время вызова; в возврате — копия в строку, указатель не наш, если заголовок не говорит иного.
- Объектный глобал — значение, а не ссылка: `const NSString *` читается один раз при загрузке и переходит так же, как `@`-возврат уровня 1 (NOTES «ObjC bridge»): `NSString`/`NSNumber` — нашим значением, любой другой объект — хэндлом, чей +1 никто не забирает обратно, потому что у бессмертного глобала нет владельца, которому его вернуть. `const` читается у самого указателя, не у того, на что он указывает.
- `^`-возврат — сырой указатель, а не объект: освобождать его смертью обёртки значило бы освобождать то, что объектом не является (`malloc`, `-[NSData bytes]`, `CGColorSpaceCreateDeviceRGB`). Обёртка помнит, на что указывает, и сообщений не принимает; кто освобождает — дело биндинга.
- CF-объекты — по аннотациям `CF_RETURNS_RETAINED`/`CF_RETURNS_NOT_RETAINED`, которые clang видит в AST, иначе по правилу Create/Copy против Get из имени функции, как у ARC. Объект держит RC, `CFRelease` — в деструкторе; toll-free bridged типы отдаются уровню 1 как `id`.
- Ошибка через код возврата или `errno` — не исключение моста; превращать её в `ex-info` — дело биндинга.

**Вызов внутрь.** Колбэк с `void *context` (`qsort_r`, `dispatch_async_f`, CF-наблюдатели) несёт Clojure-fn в контексте и садится на трамплины по форме возврата уровня 1; тело исполняется под `host_depth` и не паркуется (§5 «Вызов внутрь: делегат не паркуется»). Голый указатель на функцию без контекста требует своей точки входа на замыкание; без JIT на iOS это заранее собранный пул трамплинов, как у libffi closures на iOS, — по триггеру. Колбэки реального времени (аудио render) — отказ: там нельзя аллоцировать и трогать RC, это работа хоста.

**Переносимость.** Классификация аргументов — по архитектуре (AAPCS64 против SysV x86_64), и на x86_64 действует тот же список отказов, что у уровня 1; при реализации это строка в `docs/portability.md`. На Linux и Android уровень тот же, меняются только заголовки SDK.

**Первый срез: что он поправил в этом разделе.**
- **Разбор направляется именами, а не заголовком целиком.** Полный AST зонтика UIKit — 279 МБ JSON; имена из `:refer` — это и есть объявленная граница (§5 «Объявленная граница»), поэтому они же вход разбора, а `:refer :all` отказывает: перечислять нечего.
- **Значение константы считает clang, а не читатель AST.** В JSON-дампе значение лежит на `ConstantExpr` инициализатора, и его нет ни у неявно пронумерованной константы `enum`, ни у `#define`. Поэтому разбор просит clang свернуть сами имена — одним `enum : long long`, где инициализаторы и есть запрошенные имена; что не свернулось, отваливается по строке своей диагностики и классифицируется вторым дампом. Отсюда и `#define` даром: целочисленный макрос сворачивается так же, нецелочисленный отказывает с текстом clang'а.
- **Разбор — шаг сборки, а не действие рантайма.** Устройство не несёт ни clang'а, ни SDK, а C-only хост не умеет подпроцесс; поэтому сгенерированный `pippin/c/<Module>.clj` лежит на load path программы (в `.app` — рядом с экраном), и `require-c` его только загружает. Поставщик, запускающий генератор по требованию в dev, — дело dev-клиента (§3 «Dev client»).
- **Функции в первом срезе не вары, а строки отчёта.** Вар, который резолвится и бросает на вызове, прячет отсутствие среза за ошибкой рантайма; «Unable to resolve <имя>: вызов — второй срез» отказывает в самой ранней точке и не фиксирует сигнатуру, которую второй срез может отвергнуть (вариадики, структура по значению). Структуры (`deflayout`) — там же.
- **Оба бэкенда читают глобал одинаково.** Скомпилированный юнит — и в dev, и в `--closed` — исполняет свою `ns`-форму и находит разобранный модуль, как и со Swift-стабами (§5 «Объявленная граница»), так что глобал читается тем же `dlsym` при загрузке. «Прямое обращение в компиляторе» отложено: генератору C нужны заголовок и флаги SDK в драйвере компиляции, а выигрыша нет — чтение одно на процесс, дальше в варе число.

**Второй срез: что он поправил в этом разделе.**
- **Прототипы уровня 1 обобщены, а не продублированы.** Получатель ушёл из прототипа и стал первыми словами целочисленного файла регистров, который заполняет вызывающий: метод тратит на `self`/`_cmd` два слота из x0–x7, блок — один на себя, C-функция — ни одного. Байты и регистры те же, что и были: прототип метода и до того объявлял восемь целочисленных параметров. «Восемь вместо шести» — не второй набор прототипов, а один набор с базой.
- **Типы заголовка приходят в словаре кодировок Objective-C.** `(c-fn* "UIApplicationMain" "i" ["i" "^*" "@" "@"])`: разбор переводит desugared-написание clang'а в те же кодировки, которые читает диспетчер уровня 1, поэтому `signature_shape` и `classify_struct` — одни, а не вторые. Тип возврата desugar'ится объявлением переменной этого типа: своего desugared-написания у типа функции в AST нет.
- **Агрегат по значению — отказ до следующего триггера.** Кодировка структуры (`{CGRect={CGPoint=dd}…}`) в JSON-AST не лежит, а `@encode` виден только в сгенерированном коде, не в дампе; пока разбор её не строит, `classify_struct` для C просто не достигается. Триггер — API, где структура по значению и есть API (`CGContextFillRect`).
- **Оба бэкенда зовут через один диспетчер.** «Прямой вызов из сгенерированного C через `#include` заголовка» снят: заголовки платформы — Objective-C, а юниты компилируются как C17 (`-std=c17 -Wpedantic -Werror`, `CljCompiler/jit.c`), так что `@interface` там не соберётся ни при каком sysroot. `c-fn*` отдаёт обычное значение-fn, и скомпилированный юнит зовёт его, как любую другую fn, — то же решение, что у глобала в первом срезе. Если прямой вызов понадобится, дешёвый путь — локальный для юнита указатель `static int (*p_UIApplicationMain)(int, char **, const void *, const void *)`, разрешаемый один раз в инициализации юнита: unboxed-аргументы, типы из заголовка, чистый C17 и без флагов SDK. Это свой срез.

**Порядок.** Первый срез — декларации и константы: закрывает числа, которые экран писал руками (сделано). Второй — вызов функций и объектные глобалы: `UIApplicationMain` ушёл из `main.c`, имя уведомления доходит до `NSNotificationCenter` (сделано). Стабы для `static inline`, кодировка структуры, колбэки без контекста и прямой вызов в компиляторе — по триггеру. Статус — §10, шаг 8b.
