### Замыкания через границу: цвет живёт в Swift
Clojure-функция цвета не имеет: с корутинами ждать может любая, «ждёт» — событие исполнения, а не тип. Swift-замыкания цвет имеют. Мост читает цвет из Swift-сигнатуры и адаптирует; Clojure-сторона ничего не помечает.

**Каноническая форма одна — `Value`.** Три способа позвать, выбор на Swift-стороне и всегда статический (Swift сам не даст позвать `async` из sync):
- `callAsFunction(_ args: Value…) throws -> Value` — синхронно на потоке вызывающего.
- `callAsync(_ args: Value…) async throws -> Value` — спавнит корутину, Swift-Task приостанавливается через `withCheckedContinuation` до результата; внутри функция ждёт свободно.
- `callDetached(…) -> Task<Value, Error>` — запустить и не ждать. «Промис» есть, но его попросили явно.

Типизированные адаптеры сверху — `closure<A,B,R>() -> (A,B) throws -> R` и `closureAsync()`: дженерик-обёртка создаётся там, где сигнатура известна (стабы из symbol graph знают тип параметра; ObjC — `@convention(block)` с сигнатурой из type encoding; рукописный Swift — явно). Арность и типы проверяются при создании обёртки, не при вызове. Замыкание держит `Value` (+1 → SHARED, атомарный счётчик). Ошибки: `throws`-сигнатура → `ClojureError`; не-`throws` (большинство UIKit) — в dev `fatalError` с Clojure-трейсом, в prod лог + значение по умолчанию, настраивается на стабе.

**Swift-closure → Clojure** — host-fn с одной арностью. Синхронное — прямой вызов. `async` — вызов запускает Task, текущая корутина приостанавливается, результат возвращается значением; для Clojure это синхронная функция.

**Ошибка «ожидание внутри синхронного host-вызова».** Внутри Clojure-мира не возникает никогда: Clojure-код всегда на корутине (точка входа, `go`, обработчики UI-бэкенда, REPL-eval, main-носитель с affinity `:main` крутит корутины из run loop). Возникает только на синхронном входе из Swift: Swift ждёт значение сейчас, приостановиться нельзя — та же причина, что у sync-замыкания без `await`. Политика: ошибка. **Не** блокировка — поток не замораживается никогда; **не** возврат `Task` — это динамическая раскраска по факту исполнения, footgun core.async «получил канал вместо значения», и побочные эффекты до точки ожидания уже случились. `callBlocking` — явный opt-in на не-main потоках. Выходы: `callAsync`, `(go …)` в колбэке, `callBlocking`.

Гвард — `host_depth`: трамплины инкрементируют при входе из Swift и декрементируют при выходе; ожидание разрешено только при `host_depth == 0`, даже если технически под Swift-фреймами лежит стек корутины (реентерабельность посреди чужой операции, например layout-колбэка). Статически: стаб знает, что параметр — sync-замыкание, а у переданной функции есть факт «может ждать» → предупреждение при компиляции. Для сравнения: `DispatchSemaphore.wait()` на main в Swift — тихий фриз; у нас ошибка с трейсом до места ожидания.

**Изоляция на нашей границе сводится к асинхронности.** Генератор печатает `async`-thunk, который `await`'ит изолированный вызов, а несёт его существующий async-мост — единообразно для `@MainActor`, для пользовательского `@globalActor`, для изоляции по экземпляру актора и для любой изоляции, которую Swift добавит позже, потому что «попасть на актор» в Swift и **значит** `await`. Механизм гибкий именно этим: на каждый вид изоляции новый не изобретается.

**`@MainActor` — это `affinity: .main` на уже существующем мосту.** `callAsync`/`callDetached` уже принимают `affinity:` со значением `.main`; `Value(asyncFunction:)`/`closureAsync` уже превращают `async`-замыкание Swift в обычную синхронную Clojure-fn с парком на кадр наружу. Нового не строится ничего — генератору остаётся узнать аннотацию и вставить обёртку. И бесцветность здесь платит: `@MainActor`-замыкание становится обычной синхронной Clojure-fn, которая паркуется, пока main-носитель её не исполнит и не вернёт значение; в Swift вызывающему пришлось бы стать `async`.

Две обязанности на этой обёртке: **не прыгать, когда уже на main-носителе** (иначе main ждёт main — тот самый GCD-паттерн, который §4 в пункте про affinity описывает как «сообщение владельцу»), и **громко падать там, где парк нелегален**, то есть когда Clojure-fn позвали из Swift синхронно, с поднятым `host_depth` (выше, «ожидание внутри синхронного host-вызова»).

**Цена изоляции — не обёртка на символ.** Прыжок **условный**: на main-носителе он не делается (это первая из двух обязанностей выше, §4 «сообщение владельцу»), и выполняет его один общий хелпер, — поэтому изолированный символ стоит стаба, маршрутизированного через один механизм, а не собственного thunk'а. Доля изолированного велика (у SwiftUI — 30,6 % поверхности), и настоящая обязанность на такой доле не в коде, а в **корректности классификации**: пропущенный изолированный символ — отказ в рантайме там, где Swift дал бы ошибку компиляции.

**Что стабы стирают — вслух, как цена.** Строгой проверке конкурентности Swift 6 у нас соответствия нет: изоляция актора, которая в Swift была бы ошибкой *компиляции*, через стаб становится нашей проблемой рантайма — значит решается в генераторе, а не обнаруживается. `Sendable` обойдён по построению — наш бокс переезжает `@unchecked` (выше), — поэтому проверка гонок данных Swift на нашей границе не держится.
