## 5c. Инструментарий: nREPL, LSP
**nREPL — сразу.** REPL-интеграция редакторов (Calva, CIDER, Conjure) идёт через nREPL, не через LSP; для Clojure-разработчика это важнее LSP. Протокол в рантайме — bencode + `eval`/`load-file`/`complete`/`info`, сотни строк — и существующие клиенты подключаются к интерпретатору на симуляторе или устройстве как к обычному Clojure.

**clojure-lsp — как есть.** Синтаксис наш = Clojure: навигация, rename, find references, форматирование, рефакторинги, неиспользованные вары (clj-kondo под капотом) работают с первого дня. Не дублировать.

**Свой LSP — тонкий клиент аналитора-библиотеки (§3), когда решётка фактов заработает.** Ценность только в том, чего clojure-lsp не знает:
- диагностика: ⊥-конфликты с двумя точками, `:strict`-предупреждения, «всегда nil» — та же структура, что у CLI (§3 «Диагностика»), с `relatedInformation` на вторую точку и quick fix там, где подсказка вычислима; планка информативности общая, LSP — второй рендер одних данных, а не свой набор текстов;
- hover: выведенный тип, shape, nullability, эффекты, owned/borrowed;
- semantic tokens: подсветка «может ждать», `^:unsafe`-зон;
- inlay hints: бокс/unboxed — `@code_warntype` в редакторе; призрачный префикс `await`/`try` перед вызовом неявно async/throws-функции — убедительнее одной подсветки, т.к. текст, а не только цвет; `await?` там, где факт «может ждать» — ⊤, ничего — где известно, что не ждёт;
- автодополнение из ожидаемой схемы в позиции курсора (§3: теги и атрибуты hiccup, ключи `:map`-опций, `:enum`) и из symbol graph — по всему SDK, а не по тому, что уже в мосту: **индекс жадный, генерация ленивая** (§5), извлечение графов объявленных модулей не запускает swiftc вообще. Символ живёт в трёх состояниях: в мосту (зовётся из REPL сейчас); в индексе без стаба (принятие дополнения добавляет его в множество генерации — как auto-import); в индексе и невозможный (серым, с причиной из отчёта генератора). Дополнение членов требует типа приёмника, то есть трекает качество вывода фактов — на ⊤ деградирует до нечёткого поиска по модулям с ранжированием. В dev индекс шире dev-шелла: «есть в SDK, нет в этом шелле — пересобрать» и есть триггер `require-swift` (§3);
- go-to в host-код: от `(.string formatter)` к Swift-декларации; hover — doc-комментарий и availability из графа.

Два сервера на один файл (VS Code и Neovim умеют): clojure-lsp — рефакторинги, наш — семантика. Позже, если аналитор станет полнее clj-kondo (у нас резолв есть, у kondo нет), можно закрыть и синтаксический слой — не приоритет.

Сервер — JSON-RPC над аналитором, на нашем же Clojure, скомпилированном в нативный бинарь (dogfooding, быстрый старт). Требование к аналитору — инкрементальность на уровне формы с эпохами варов — уже есть от dev-режима.

**Макросы раскрываются по-настоящему.** clj-kondo макросы не исполняет — отсюда хуки: каждый пользовательский макрос надо описывать отдельно, иначе всё внутри него — ⊤ или ложные срабатывания; на практике проще отключить kondo целиком. У нас аналитор содержит интерпретатор и раскрывает любой макрос как компилятор: тело `defmacro` выполняется, результат анализируется. Ничего описывать не нужно, hiccup-макросы и DSL проверяются как обычный код. Цена — аналитор обязан **исполнять** top-level формы проекта, иначе вары-реестры схем пусты, протоколы не зарегистрированы, схемы не вычислены. Исполнять всё нельзя: `(start-server!)` на открытие файла недопустимо. Ответ — та же классификация эффектов, что у ленивых `def` (§4): **режим анализа** загрузки ns — формы с эффектом `registration` (`defmacro`, `defprotocol`, `defmethod`, `extend-type`, схемы и записи в вары-реестры) исполняются, чистые `def` остаются thunk'ами, формы с IO-эффектами пропускаются, неизвестный эффект → пропуск. Нераскрывшийся из-за пропуска макрос → ⊤ дальше по форме, не ошибка. Режим общий для LSP и компилятора: компилятору для раскрытия макросов в закрытом мире нужно загрузить те же ns, и без этого режима AOT поднимает серверы из `defonce`, как в JVM-Clojure.

**Рассматривается: бит `macro-time` на варе — спрос, а не разрешение.** Эффекты говорят, что *безопасно* исполнить, не что *нужно*. Для чистых `def` спрос даёт ленивость сама: раскрытие зовёт `helper` → форсится thunk. Бит нужен там, где спросом не форсится: top-level записи в реестры через атом (`atom-write` → сейчас пропуск → макрос по реестру даёт ⊤; с битом форма исполняется, если её цель достижима из тела макроса), IO на macro-time (`(def schema (slurp …))` — LSP пропускает, AOT исполняет), фазы для компилятора (macro-only хелперы вон из образа на устройство — Racket phases, но выведенные). Вычисление — достижимость от каждого `defmacro` по множеству ссылок на вары из сводок (поле нужно tree-shaking'у и так); монотонный бит, без второго прохода по дереву — повторно только исполняются отложенные формы по готовому `clj_node`. Ограничения: граф неточен при `resolve`/higher-order → бит консервативный, fallback тот же ⊤; отложенная форма исполняется позже своей позиции. Мера: на загрузке core — сколько thunk'ов реально форсится против «исполнить всё, кроме IO»; если выигрыша нет, бит остаётся только ради фаз и ждёт tree-shaking'а.
