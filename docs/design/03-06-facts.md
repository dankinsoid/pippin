### Вывод фактов: решётка, два прохода, уточнения
**Суть.** Не система типов, а абстрактная интерпретация над решёткой фактов ради оптимизации и предупреждений. Язык остаётся динамическим: неизвестное = ⊤, ⊤ ничего не ломает (бокс + молчание), худший случай = Clojure как есть. Вывод — по использованию, без обязательных аннотаций; аннотации только в core-библиотеках и на границах по желанию.

**Собрано из прецедентов, не изобретено.** Julia — динамический язык, вывод ради оптимизации, абстрактная интерпретация над решёткой с widening, `@code_warntype` показывает, где не вывелось; ближайший образец. Dialyzer — success typings: вывод из использования, предупреждение только при доказанном конфликте, ноль ложных срабатываний, опциональные `-spec`; медленный из-за богатых типов и фикс-пойнта по всему приложению — учесть. Typed Racket occurrence typing / TypeScript type guards / Kotlin smart casts — уточнение на предикатах. Zig comptime — функции, возвращающие типы, выполняются при компиляции. Malli — схемы как данные, `m/=>` для функций. OCaml/HM — **не** образец: унификация делает язык типизированным, ошибка вместо ⊤.

**Решётка.** Факт = вид + решётка: ⊤ «не знаю», ⊥ «конфликт», join на слиянии веток, meet при уточнении, widening для сходимости. Обход дерева один; каждая форма даёт transfer-функцию для каждого вида факта. Сводка функции = все факты о параметрах и результате. Расширяемость — в видах фактов и transfer-функциях, декларативно; не открытый API «инжект кода в обход» (протекает AST, ломается при каждом изменении, три пользователя).

Виды фактов — все в одной решётке, один обход, один фикс-пойнт:
- **Тип**, включая singleton-типы (константы: `[:= :id]`; enum = объединение singleton'ов). Литеральный keyword в `(:id m)` — singleton, поэтому слот shape'а известен без спецслучая. Compile-time вычислимость — производный факт (чистота ∧ все входы singleton), отдельно не хранится.
- **Nullability** — отдельно от типа, уточняется независимо (`some?`, `if-let`, `when`); главный источник `(:field nil)`-багов.
- **Shape** — ключи и типы полей; из литералов, схем, парсинга, использования.
- **Escaping** — local / escapes / captured. Регионы, стек, reuse.
- **Может ждать** — suspends / no / ⊤. Гвард `swap!`, подсветка, main-thread.
- **Ownership** — owned/borrowed на параметрах, uniqueness на локалах. Perceus.
- **Эффекты** — множество: IO, atom-write, host-call, throws, nondeterministic, registration. Fusion, ленивые def, CSE. `registration` — запись в таблицы рантайма (вар, протокол, мультиметод, вар-реестр схем, `derive`): отдельно от `atom-write`, потому что режим анализа (§5c) исполняет первое и пропускает второе.
- **Throws** — какие `ex-info`/host-ошибки; Swift `throws` через стабы. Убрать error-check в C там, где не бросает.
- **Thread affinity** — «требует main» (UIKit-стабы = `@MainActor`) / «любой». Статическая проверка «UI из `go` на пуле» — как Swift 6, но выведено.
- **Публикуется** — статическая версия SHARED-флага. Не «пересекает поток», а flow-анализ по закрытому списку стоков: запись в разделяемую ячейку (var, атом, канал, ячейка lazy seq), захват при spawn, экспорт в хост. Не течёт ни в один → неатомарный счётчик без рантайм-проверки; течёт → пометить при создании. Тот же анализ даёт move для `>!`: локал мёртв после отправки → передача единственного владельца, без share.
- **Свежесть результата** — функция возвращает только что созданное → у вызывающего reuse без проверки rc==1.
- **Строгость / потребление seq** — целиком тут же / частично / убегает. Eager вместо thunk'ов, не держать голову.
- **Захваты замыкания** — множество захваченных локалов и их факты.
- **Аллоцирует / нет** — для горячих путей, `^:no-alloc` в стиле `@nonallocating`.
- **Арность на сайте** — без seq для `& rest`, без диспатча.
- **Позиция хвостового вызова** — `musttail`.

Не делать: диапазоны чисел ради bounds-check elimination, termination, точные размеры коллекций — дорого, редко окупается.

Половина списка — то, что Swift 6 сделал обязательными аннотациями (`async`, `throws`, `Sendable`, `@MainActor`, `borrowing`, `@escaping`). У нас — выведено, ⊤ как честное «не знаю». Gradual в широком смысле.

**Два прохода.**
- Проход 1, bottom-up по графу вызовов: сводки функций из тел — требования к аргументам по использованию, факты результата. Рекурсия — фикс-пойнт с widening.
- Проход 2, top-down по сайтам: знание об аргументе у вызывающего meet-ится с требованием из сводки. Обратное направление — join того, что все загруженные вызывающие передают в параметр — тоже факт аналитора, не привилегия AOT: dev-режим знает всех вызывающих до следующего `def` и держит join под эпохой множества вызывающих (обратный индекс «кто зовёт `f`», ведётся при каждом `def`), потребитель — self-optimizing узел с guard'ом; закрытый мир лишь снимает guard. ⊥ → ошибка с **обеими** точками: «здесь используется как мапа с `:key` (строка N), сюда передаётся shape без `:key` (строка M)». Сообщения показывают места и shape'ы, не абстрактные типы (анти-OCaml).
- Не HM-унификация: constraint solving над решёткой ограниченной высоты — дешевле, никогда не падает жёстко.

**Уточнения (occurrence typing).** На предикатах, не на `if`. Предикат несёт факт «истина ⇒ аргумент X; ложь ⇒ аргумент Y». Core-предикаты (`some?`, `number?`, `map?`, `instance?`, `=`) — со сводками; `if`/`when`/`cond`/`case`/`and`/`or`/`if-let` — встроенные формы, применяющие уточнения условия к веткам. Для пользовательских предикатов уточнение выводится из тела: `(defn user? [x] (instance? User x))` получает refinement автоматически. Аннотация нужна только для непрозрачных (host) предикатов. Макросы расширяются в эти формы и получают уточнения бесплатно.

**Один механизм: схема денотирует факт.** Решётка — закрытая C-структура; всё, что хочет на неё повлиять из кода, выражается схемой-данными в фиксированном словаре: `:any :nil :int :double :number :string :keyword :symbol :boolean :map :vector :set :seq :tuple :cat :* :? :maybe :or :and :enum := :multi :ref :fn :=>` — special forms языка фактов, как ~16 special forms у самой Clojure. У каждого тега две интерпретации одного значения: абстрактная в аналиторе (`schema → fact`: `:int` → {fixnum, long, bigint}, `[:maybe X]` → X ∪ nil, `[:or …]` → join, `[:and …]` → meet, `[:= x]`/`[:enum …]` → singleton'ы; структурные `:tuple`/`:cat`/`:map` спускаются в дочерние узлы литерала) и конкретная в рантайме (валидация значений). Проверка узла против схемы — три значения на существующих операциях: `fact ⊑ fact(schema)` — ок, `meet = ⊥` — предупреждение, иначе ⊤ и молчание. Обратное вложение `fact → schema` тотально (тип-множество → `[:or …]`, nullability → `[:maybe …]`, singleton → `[:= x]`, дескриптор → `[:record User]`), round-trip тождественен — поэтому решётка наружу не видна никогда, интерфейс в обе стороны — данные словаря. Словарь стабилен, решётка растёт по триггерам (счётные факты под `{:min 4 :max 4}`, shape'ы); до того проекция просто теряет лишнее. Почему словарь схем, а не «факт как данные»: факт беднее схемы — факт говорит «мапа», схема — «мапа с этими ключами и вот такими альтернативами `:multi`», а именно это нужно LSP и рантайм-валидации; и словарь в форме решётки ломал бы формат для всех библиотек при каждом её расширении.

**Расширение — comptime-раскрытие, как макросы над special forms.** Вызов внутри схемы исполняется интерпретатором в режиме анализа (§5c), результат обязан быть данными словаря: `(matrix :int 4 4)` → `[:vector {:min 4 :max 4} [:vector {:min 4 :max 4} :int]]`. Это и есть дженерики — Zig comptime: типы как значения, функции над ними. Тот же примитив — трансфер-функция: `:=>` принимает в позиции результата функцию от схем аргументов, `[:=> [:cat :coll :any] (fn [coll _] coll)]` для `conj` — Zig'овский `@TypeOf(coll)`; от `matrix` отличается лишь тем, что входы — выведенные факты аргументов, а не параметры от автора. Типовые переменные (`[:=> [:cat T :any] T]`), если понадобятся, — сахар поверх, и слабее: только унификация. Для тел, которые аналитор видит, ни то ни другое не нужно — сводка выводится; объявление — для непрозрачного: хост, C-builtins, границы. Таблица сигнатур в `facts.c` — AOT тех же функций для ядра ради скорости; критерий самосогласованности — всё, что она знает, выразимо `:=>`-метой на `defn` в `core.clj`, а невыразимое — дыра словаря, не повод для второго механизма. Правила: чистота и бюджет шагов (зацикленная схемная функция иначе вешает LSP; IO в схемной функции — ошибка автора, не ⊤); мемоизация по схеме аргументов на сайт; монотонность желательна, но немонотонная функция стоит точности, не завершимости — widening есть; для непрозрачного тела объявление **доверяется**, как `^long` и Swift-стаб, где тело видно — meet с выводом.

**Три якоря — и четвёртого нет.** Как факты прикрепляются к коду; одна решётка, все необязательные: (1) **мета на варе** — `(defn view {:=> [:cat ::view] :any} [v] …)`, то же, что `m/=>`: факты аргументов и результата, `meet` с выведенной сводкой, не замена; расхождение аннотации и тела — ⊥, ошибка с обеими позициями, потому что неправа одна из сторон; ⊤ на входе в аннотированный параметр — предупреждение (см. «Строгость»). Единственный способ сказать «этот параметр ожидает X»; (2) **выведенное уточнение предиката** — из тела, без записи (`(defn user? [x] (instance? User x))`); (3) **объявленное уточнение** для того, чьё тело не анализируется — хостовый предикат, валидатор: «истина ⇒ аргумент N получает факт, вычисленный из аргумента M», M comptime-вычислим. Локальная аннотация сводится к нему: `(assert-schema X v)` — вызов валидатора с refinement на `v`, отдельного синтаксиса на биндинге нет. Номинальные типы — `defrecord`/`deftype`/host — уже дескрипторы; структурные «свои типы» — вар со схемой и `[:ref `User]`. Открытый реестр (теги hiccup, события re-frame из разных ns) — тоже просто вар с `:multi`, дописываемый обычным кодом; `:ref` резолвится через вар под эпохой, как любая сводка. Цена якорей 1 и `:ref`: проход 1 перестаёт быть чистым по построению — таблица фактов становится кэшем с ключом (дерево, эпохи упомянутых варов); это то, что pass 2 и так обещает для сводок, триггер просто наступает раньше.

**Поведенческие факты объявляются так же, но почти никогда.** Схемы описывают значения; escaping, эффекты, throws, «может ждать», владение — факты о функциях и сайтах, они выводятся из тел. Объявлять — только где тела нет: хостовая граница, и там словарь уже есть, Swift'овский — `throws`, `async`, `@escaping`, `@Sendable`, `sending`, `borrowing`/`consuming` переезжают в сводки из symbol graph, руками не пишутся. На Clojure-стороне редкий случай (обёртка над непрозрачным хостом, `:strict`-ns) — properties той же `:=>`-схемы: `[:=> {:effects #{:io} :throws [Ex]} [:cat …] :any]`; Malli properties-мапу допускает и игнорирует, аналитор читает. Escaping и владение не объявляются никогда: вывод плюс отметка «сохраняет аргумент» у стабов; пользовательский рычаг — `transient`, не аннотация (§3 «Явные двойники»).

**Malli — совместимое подмножество, не ориентир.** В пересечении наши схемы — валидные Malli-данные: знакомый синтаксис и валидация тем же значением бесплатно. За пределами пересечения расширяемся без оглядки: функция в позиции результата `:=>`, properties с эффектами, comptime-конструкторы в любой позиции, «остаток вектора против сигнатуры функции в позиции 0» для компонентных голов hiccup, счётные факты. `:multi` интерпретируется только с диспатчем по позиции с singleton'ом — голова вектора, ключ мапы; произвольная `:dispatch`-функция над фактом невычислима → ⊤. `:ref` над не-литералом не разворачивается — даёт верхний вид (`vector`); над литералом рекурсия конечна по построению. Spec и другие библиотеки подключаются раскрытием в словарь, как пользовательский тег.

**Поток фактов только вперёд.** Специализация вперёд есть: обратный индекс «кто зовёт `f`» и join аргументов вызывающих в параметры def'нутой функции (§10 шаг 6). Возвратному дженерику нужен *ожидаемый* тип, текущий **назад** — с сайта в тело; решётка идёт вперёд (аргументы → результат), а двунаправленный вывод — другое направление потока, а не его расширение. Поэтому решено: тип дженерика известен на вызове и вверх не распространяется (§5 «Дженерики»).

**Схема malli и типовой параметр Swift совместимыми не делаются.** Они разного рода: схема — *предикат над значениями*, она валидирует; типовой параметр — *тип на компиляции*, он выбирает код. `[:and int? pos?]` — нормальная схема, за которой нет никакого Swift-типа. Объединение требовало бы, чтобы каждая схема была называемым Swift-типом, и было бы ложным тождеством глубже, чем у `reify` (§4): там совпадала *форма*, здесь совпал бы *концепт*. Ловушку при этом молчать нельзя: схемная переменная, доехавшая до дженерик-вызова Swift, — диагностика анализа («тип должен быть известен здесь, схема его не даёт»), а не вызов, который тихо не сработает.

**Рантайм-инструмент: нативно и минимально.** Слой 3 («схема на границе = shape ниже») окупается, только если проверка на границе дешева настолько, что остаётся в проде. Поэтому `validate`/`explain`/`coerce` над словарём — в рантайме, как вторая интерпретация тех же тегов: тот же обход, над значениями вместо фактов. Константная схема на сайте специализируется компилятором в прямую проверку без интерпретации — чего у Malli нет по определению: он компилирует схему в замыкания в рантайме. Тот же валидатор — dev-инструмент: доверенные объявления и трансфер-функции на реальных значениях, hiccup, собранный в рантайме, граница с хостом. Сам Malli — загружаемая библиотека для генераторов, трансформеров, humanized-ошибок; его схемы работают, потому что словарь общий, и это элемент корпуса совместимости.

**Пределы, честно.** Это абстрактная интерпретация с объявленными фактами, не система типов с гарантиями; сила — из comptime-вычислений над схемами, не из теоретико-типового ядра. Нет вывода типовых переменных через неизвестные тела — только вычисление; объявления для непрозрачного не доказываются, только проверяются в dev; решётка ограничивает точность независимо от богатства словаря.

**Три трудных места — и что решётка с ними делает.**
- Протоколы: `(:key value)` берёт сводку из реализации `IFn` у `Keyword` («аргумент `ILookup` ∨ nil»), не хардкод паттерна. Рядом структурный факт «если shape, то ключи ⊇ {`:key`}». Поправка: `(:key m)` без ключа в Clojure — nil, не ошибка → ценность вывода в *результате* (тип поля из shape, или «всегда nil» → предупреждение только в `:strict`), а не в требовании. Конформансы — по таблице (закрытый мир — полная; dev — известные, остальное ⊤). Вызов протокольного метода: результат = join по известным реализациям.
- Swift-типы не теряются: стабы рождаются из symbol graph вместе со сводками (`[:=> [:cat host/Date] host/String]`); host-типы — номинальные факты с иерархией из метаданных; `Codable`-конверсия даёт shape с типами полей точнее любого вывода. ⊤ только у ObjC-рантайма без объявлений и у `Value` из Swift без схемы.
- Мультиметоды: протокол с диспатчем по данным. Dev: таблица и иерархия мутабельны → результат ⊤, требования — только от функции диспатча. Закрытый мир: результат = join тел; dispatch-value singleton → точный метод. `prefer-method`/`:default` — ветки того же join.

Общее правило: сомнение → ⊤, ⊤ ничего не ломает.

**Строгость.** Три ступени по силе знания, не по вкусу. **⊥ — ошибка, всегда и в любом режиме:** доказанное несовпадение на сайте (передаётся точно не то, что требуется), аннотация, противоречащая телу. Это единственное, что останавливает компиляцию, и единственное исключение из инварианта ниже — не мнение инструмента, а доказанный сбой в рантайме, показанный раньше. **⊤ в объявленный параметр или результат — предупреждение, по умолчанию включено, выключается на ns:** аннотация — явная просьба быть типизированным, ⊤ на её входе — то, о чём просили сказать. Против *выведенных* требований ⊤ молчит: при ожидаемых 40–50 % статического покрытия это был бы шум на каждом втором вызове. **`:strict` (на ns)** — ⊤ и против выведенных требований на границах функций, «всегда nil» тоже; для кода, который хочет быть типизированным целиком. `:off` гасит предупреждения, не ошибки.

**Скорость компилятора — три предохранителя.** Решётка ограниченной высоты: полиморфизм ≤4 shape'ов (дальше ⊤), числа int/double/number/⊤, никаких бесконечных уточнений. Локальный вывод всегда (микросекунды); межпроцедурный фикс-пойнт — закрытый мир или инкрементально по эпохам варов: сводка хранится с эпохой, сайт использует её как inline cache, переопределение сдвигает эпоху → сайт откатывается на generic-путь и пересчитывает при следующем использовании; на циклах в dev — widening сразу.
