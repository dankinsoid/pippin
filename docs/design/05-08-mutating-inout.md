### `mutating`, `inout`, `borrowing`, `consuming`
**`mutating` — это `inout self`**, буквально, а не по аналогии: Swift показывает это в неприменённой ссылке на метод — `Foo.regularMethod` имеет тип `(Foo) -> () -> ()`, а `Foo.mutatingMethod` — `(inout Foo) -> () -> ()`. Правило генератора поэтому **одно**: `inout`-параметр, включая неявный `self`, становится дополнительным возвращаемым значением, — и `mutating` выпадает из него без особого случая. Оно обобщается: несколько `inout` возвращают несколько значений, а `mutating`-метод, который ещё и возвращает результат, возвращает и новый `self`, и результат (порядок — конвенция, её надо зафиксировать).

**Бокса поэтому нет.** Бокс был бы неверен, и по причине проще семантики значений: там нечего боксить — ссылки нет. `inout` в Swift — copy-in/copy-out; физически это обычно указатель, по которому мутируют на месте, а неразличимыми эти два прочтения делает закон исключительного доступа, — поэтому наш мост делает семантически верное и теряет только оптимизацию in-place, не корректность. Расхождение «мутация видна через каждый алиас», которое создал бы бокс, не возникает вовсе.

**Следствие для записи:** `mutating`-метод нельзя печатать `.`-формой, потому что `(.append! s x)` обещает мутацию получателя, которой не происходит. Разделение: **`.`-форма — вызов на ссылке** (класс, ручка); **обычная функция — значение внутрь, значение наружу** (`inout`, `mutating`, структуры). Значит `(append s x)`.

**`borrowing`** — аннотация владения ради скорости, а не семантика: делать нечего, ручка передаётся как есть. **`consuming`** — тоже ничего для копируемого типа (Swift копирует там, где нужно), но для **`~Copyable`** ручка после вызова недействительна по правилам Swift, тогда как Clojure владеет ею и размножает свободно — там генератор обязан отказать, а не угадать.

**Конвенция возврата (решено 2026-10-03, второй срез §10 шага 8).** Вызов возвращает новые значения `inout`-параметров в порядке объявления — `self` первым, потому что он и есть первый параметр `(inout Foo) -> (args) -> R`, — а за ними результат, если он не `Void`. Одно значение возвращается как есть, несколько — вектором. Так `mutating`-метод без результата, самая частая форма, возвращает новый `self` без обёртки и встаёт в `swap!`, `update` и `->` как есть: `(swap! a PippinFixture/Counter.bumped :by 1)`. `mutating` с результатом даёт `[self' r]` под деструктуризацию, `func f(_ a: inout Int, _ b: inout Int) -> Bool` — `[a' b' r]`. Сеттер свойства структуры — `mutating set`, то есть тот же случай: `(Point.set-length p 3.0)` возвращает новую структуру, а бокс `p` остаётся прежним. Сеттер свойства класса меняет объект за ссылкой и возвращает nil: `self` класса не `inout`.
