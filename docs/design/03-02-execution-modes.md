### Два режима исполнения
- **Dev — скомпилированная база + интерпретируемые дельты.** Dev-сборка под устройство компилируется на `-O1` (§6b) без прямой линковки: все вызовы через вар + эпоху, поэтому переопределение из REPL долетает и в скомпилированный код. Интерпретатор исполняет только то, что прислали в REPL — одну правящуюся функцию, не весь UI на 60 fps. REPL везде, включая устройство (единственный способ исполнить новый код на iPhone). Интерпретатор — source of truth семантики, компилятор — оптимизации поверх той же программы (`clj_node`) и обязан с ним совпадать; быстрым интерпретатор обязан быть тоже (§6b «Интерпретатор до компилятора»), просто не за счёт второй реализации семантики.
- **Prod — компилятор** в C → clang. Закрытый мир.
- **Компилирующий eval на Маке/симуляторе** (C → clang → dylib → dlopen, ~100 мс) — не третий режим, а инструмент: тесты в CI гоняются через компилятор (ловим расхождение семантик), профилирование без сборки всего приложения.
