### Дескриптор типа: core-интерфейсы как слоты
Не Swift-протоколы (из C недоступны, стоят экзистенциалов) — **дескриптор типа со слотами**, как `tp_*` в CPython или метатаблицы Lua. `clj_type` уже он: `each_child/finalize/hash/equals` — первые слоты, `clj_invoke` — первый диспатч по типу. Дальше — расширение, не переписывание.

```c
struct clj_type {
    clj_header h; const char *name;
    uint64_t core_bits;            // битсет реализованных core-интерфейсов: (map? x) = один AND
    seq, first, next, count, lookup, conj, invoke, equals, hash, each_child, finalize;
    proto_table *user_protos;      // defprotocol'ы: id протокола → таблица; NULL пока
};
```

- **Core-интерфейсы** (`ISeq`, `IFn`, `ILookup`, `Counted`, `IPersistentCollection`, `Associative`, `IEquiv`, `IHash`, позже `IMeta`) — фиксированные слоты, ноль поиска: тег → дескриптор → слот → вызов. Пользовательские `defprotocol` — отдельная таблица по id, потому что их неограниченно много. Иерархию Java-интерфейсов (`IPersistentMap extends ILookup, Counted, …`) заменяет `core_bits`: `satisfies?`/`sequential?`/`coll?` — один AND, без обхода иерархии.
- **`invoke` — один слот** `(self, args, n)`. Арность — свойство объекта (`clj_fn` держит таблицу арностей), не типа.
- **`seq` обязателен, `first`/`next` — опциональный fast path.** Источник истины — seq-объект: `(first v)` = `(first (seq v))`, как `RT.first`. Прямые `first`/`next` на коллекции оправданы только там, где `seq` — O(1) view без аллокации (вектор, string, range, позже array-map); для HAMT `seq` и так строит объект. Дефолт через `seq` — норма, fast path — для четырёх-пяти типов.
- **Трейты вместо абстрактных классов** (`ASeq`, `APersistentMap` на JVM): `desc = ASEQ_TRAIT; desc.first = my_first;` — структурное копирование в C. Sequential equality/hash уже написаны один раз (`coll.c`) — это и есть `ASEQ_TRAIT`.
- **`deftype`/`reify`/`extend-type`** создают или патчат дескриптор: слот указывает на трамплин, который зовёт Clojure-функцию (интерпретатор) или сгенерированную C-функцию (компилятор). Host-обёртки тоже имеют дескриптор — поэтому `extend-type` на Swift-тип работает без создания типа.
- **Мутабельность и потоки.** Патч слота — под глобальным мьютексом протоколов; публикация трамплина — release-store, чтение — acquire (не relaxed: иначе читатель видит указатель раньше тела трамплина; JVM-Clojure живёт с benign race в `extend`, нам не стоит). Каждый патч инкрементирует **глобальную эпоху протоколов** — та же механика, что у варов: inline-кэши на узлах AST и PGO-guard'ы компилятора кэшируют результат диспатча по типу и без эпохи `extend-type` из REPL не долетит до уже закэшированных сайтов.
- **Граница запрета:** «встроенный тип × core-интерфейс» — write-once, `(extend-type String ISeq …)` невозможен (CLJS позволяет — и это источник загадочных багов между библиотеками). «Любой тип × пользовательский протокол» через `user_protos` — разрешён, это основной сценарий `extend-type`. Открыть проще, чем закрыть.
- **Интринсики компилятора** (tag-switch с inline-ветками: `first` на cons — прямой load) — дубль слота, не замена; интерпретатор ходит только через слоты. Страховка — дифференциальный property-тест: генератор коллекций × таблица `(intrinsic x) == (slot-call x)` по всем core-операциям; он же ловит разъезд интерпретатор/компилятор.
- **Кэш `hash` и `meta` — не в дескрипторе** (он общий на тип), а в объекте. Но и не в общем заголовке: `clj_header` — 16 байт без padding, `hash + meta` = ещё 16 на каждый cons и boxed double (cons 32 → 48). Layout заголовка — приватная деталь компиляции, не ABI (Swift читает только через функции), поэтому резервировать место заранее незачем: `hash` кэшируется per-type там, где окупается (map — уже, vector/string/symbol — по мере надобности), `meta` — поле только у IObj-типов (корни коллекций, symbol, fn, var), как в Clojure. Исключение — cons, `()` и seq-вьюшки (vector-seq, string-seq, array-seq, range, lazy-seq): у них нет поля, флаг заголовка `CLJ_FLAG_META` означает «есть хвостовое слово meta»; 40-байтный вариант аллоцируют только reader (позиция формы) и `with-meta`, cons из lazy-seq остаётся 32 байта (классы пула 32/40/48 — иначе +25 % на самый массовый объект). Вьюшка — тот же механизм: `with-meta` на ней отдаёт копию «размер типа + слово», а не растит каждый шаг обхода, потому что вьюшек на единицу работы больше всего, а с метаданными из них живёт считаное число.
- **Swift-сторона** получает протоколы *поверх* слотов: `Value: Sequence, Collection, Hashable` — конформансы, реализованные вызовом слотов через C ABI. В обратную сторону — Swift-тип участвует в `ISeq`, если его host-обёртка получила дескриптор с трамплинами в стабы.

Прецеденты: CPython `tp_iter`/`tp_call`/`tp_as_mapping`, Lua `__index`/`__call`, Racket CS record-type descriptors с properties, Ruby C API, jank (то же на C++-шаблонах). Наше добавление — битсет для `satisfies?`, эпоха и трамплины интерпретатора и компилятора в одном слоте.
