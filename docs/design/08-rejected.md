## 8. Что отвергнуто и почему

| Идея | Почему нет |
|---|---|
| Транспиляция в Swift-исходник | swiftc медленный, атомарный ARC, `Any`-бокс, всё равно нужны стабы |
| Swift-классы для Clojure-значений | закрывает свой RC/аллокатор/заголовок навсегда |
| Swift-замыкания как Clojure-fn | одна арность, нет IFn/meta/identity/apply, атомарный контекст |
| Honest-конформансы из `deftype` в компиляторе | расхождение семантик с интерпретатором |
| Actor для атома | `swap!` становится `await` |
| CAS-атом | retain/release гонка на указателе, hazard pointers ради JVM-дизайна |
| JIT | iOS; замена — PGO из dev-профиля |
| Свой GC | см. §7 |
| `<!!`/`>!!` | блокировка кооперативного пула |
| Генерация покрытия всего Swift SDK | дженерики не эрейзятся; никто не сделал |
| `delay` + `@` как способ ленивых глобалов | ленивость встроена в Var, синтаксис не нужен |
| Pre-pass, поднимающий имена `def` при загрузке файла | второй ридер вместо настоящего; имена из макросов не видит; затеняет core там, где JVM резолвит в core (§4 «Порядок объявлений») |
| Вывод типов только в компиляторе / отдельный анализатор | один аналитор-библиотека с тремя клиентами: интерпретатор, компилятор, LSP |
| SoA для вектора мап одного shape'а | `nth` хуже базы, персистентность ломается; место — явный dataset-тип |
| Порог 8 ключей как у `PersistentArrayMap` | 32: сравнение указателей, не JVM-`equals`; DTO с бэкенда — 5–25 полей |
| `defrecord` как единственный ответ на struct-like мапы | не покрывает данные с границы, церемония `map->User`; record = именованный shape |
| HM/OCaml-унификация | делает язык типизированным; у нас решётка с ⊤, success typings |
| Открытый API для инжекта кода в обход дерева | протекает AST; расширение декларативное: факты на варах, refinements на предикатах, схемные функции |
| Константность как отдельный факт | это singleton-тип в решётке типов; compile-time вычислимость — производная (чистота ∧ singleton-входы) |
| Мутабельные локалы (`set!` на `let`) | семантический разлом; `loop/recur` + мутабельные поля `deftype` покрывают |
| Ссылки/`Value` внутри `deflayout` | ломает isbits: копия перестаёт быть memcpy, появляются RC-корни в буферах; для этого `deftype` |
| Голый указатель с арифметикой как публичный тип | view = адрес + размер + владелец, арифметика — `slice`; `ptr` только на FFI-границе и в `^:unsafe` |
| Отмена как третий исход функции — свой сентинел рядом с `CLJ_THROWN` | наблюдаемой разницы нет. `finally` обязан бежать, скоуп обязан уметь перевести отмену ребёнка в свой `:timeout` — значит третий исход раскручивает стек, запускает `finally` и допускает явный обработчик, то есть отличается от броска только местом метки. Erlang-овский `exit` — невидимый дефолтному `catch` и ловимый явным классом — это наша семантика, записанная иначе, а не другая. Цена же реальная: второй сентинел удваивает инвариант `== CLJ_THROWN` по каждому узлу интерпретатора, каждой эмиссии компилятора, границе хоста, каналам и драйверам seq/reduce, и пропущенное место принимает сентинел за значение молча. Выигрыш был бы только если бы отмену вообще нельзя было обработать — но обработчики нужны минимум в четырёх местах рантайма |
| SoA неявно над `vector` | явный `(array Layout n)` — см. низкоуровневый слой §4 |
| Зашить SwiftUI/UIKit в компилятор | язык знает только схемы; UI — библиотека с бэкендами |
| `defdsl` как форма языка | реестр тегов — вар с `:multi`, потребитель — аннотация; форма нарушала бы инвариант «язык не меняется» (§3) |
| Директивы стоимости, меняющие поведение: явные `move`/`borrow`, пользовательские регионы для значений, атомарный счётчик руками | второй язык внутри первого; видимость стоимости дают утверждения, рычаг — явный двойник (§3 «Явные двойники») |
| Компиляция hiccup макросом (hicada/uix) | теряет данные; у нас специализация компилятором с сохранением семантики |
| Общий кроссплатформенный словарь тегов | LCD-ловушка; словарь per-backend, пересечение по факту |
| Auto Layout как основной layout | медленный, не переносится; Yoga на C в ядре |
| clojure-lsp рядом со своим LSP (два сервера на файл) | kondo не читает ветку `#?` с нашим ключом и не раскрывает макросы: в `.cljc` clean-ns удаляет нужный require, rename пропускает использования — молчаливая неверная правка, конфигом не лечится (§5c) |
| Промежуточная стадия на clojure-lsp с генерируемым конфигом kondo | на языке пока не пишут; LSP делается сразу финальным (§5c) |
| Хуки для макросов в LSP (модель clj-kondo) | аналитор раскрывает макросы интерпретатором; загрузка проекта в режиме анализа по эффектам форм |
| Списки подавлений по макросам (модель Eastwood, `:if-inside-macroexpansion-of`) | шум из раскрытий снимается по построению: линтинг только на оригинальных формах, мёртвый код по ветке (§3 «Диагностика») |
| Интерпретатор в прод-сборке | 2.5.2 + честная проверка полноты компилятора |
| Reader-тег `#location` | ненамespace'нные теги зарезервированы; `.cljc` не прочитается на JVM; макрос `(location)` делает то же |
| Неявная локация у всех функций | стоимость на каждом вызове и утечка в ABI; Swift и Rust тоже opt-in — `^:track-caller` |
| Swift-протоколы для core-интерфейсов | недоступны из C; слоты дескриптора |
| `invoke[N_ARITIES]` в дескрипторе | арность — свойство объекта |
| `extend-type` встроенного типа на core-интерфейс | write-once; разрешено только на пользовательские протоколы |
| Возврат `Task` из синхронного вызова при ожидании | динамическая раскраска по факту исполнения |
| Блокировка потока при ожидании в sync-вызове | только явный `callBlocking`, не на main |
| Пометка Clojure-функций как async | цвет читается из Swift-сигнатуры на мосту |
| `go` как IOC-макрос (state machine, как в ClojureScript) в обоих режимах | цвет по конвенции, `<!` не во вложенном `fn`; async host-замыкание — только через канал из `go`; трейс уничтожен на резюме; тащит аналитор в раскрытие макроса. Его плюс — миллион машин по сотне байт — на мобильном не нужен |
| Копирование стека корутины в кучу (Loom, Go) | в C указатели в кадры вызывающих; резерв `mmap` + ленивый коммит + `madvise` на парке |
| Многоразовые континуации, `call/cc`, клон корутины | стек нельзя скопировать на другой адрес (указатели в кадры), а клон на тот же — по определению; и RC: дубль стека удваивает ссылки без инкрементов |
| Асинхронная преемпция сигналом (Go 1.14) | она нужна ради stop-the-world трассирующего GC, которого нет; убегающий цикл ловится safe-point'ами (тик `loop`, входы в драйверы), а цена — разметка небезопасных точек (`clj_lock`, аллокатор) поверх guard-хендлера |
| Приостановка корутин и эвакуация по `didEnterBackground` | процесс замораживает система; sweep успевает в окне; на телефоне это сотни килобайт |
| Сериализация корутины, миграция между процессами, переживание hot-reload | кадры ссылаются на старый код и C-адреса; при hot-reload корутины перезапускаются |
| Tracing GC ради циклов | trial deletion над may-cycle-кандидатами; RC остаётся единственным освобождением |
| Автоматический weak по обнаружении цикла | рантайм не знает владения |
| Back-pointers на каждый retain | память ×2, retain → аллокация, отвечает не на тот вопрос |
| `~Copyable` для `Value` | не запрещает хранить, ломает ergonomics |
| Полноценный MVCC STM для `ref` | редко используется; 2PL по id ref'ов |
| NaN-boxing | PAC на arm64e, 32-битный int, double и так unboxed там, где важно |
| Генераторы / resumable exceptions / backtracking как фичи языка | корутины + `binding` + core.logic |
| Оптимизации без бюджета | любой проход деградирует в ⊤, а не падает |
| `proxy` и его обвязка (`construct-proxy`, `init-proxy`, `update-proxy`, `get-proxy-class`, `proxy-super`, `proxy-name`, `proxy-mappings`, `proxy-call-with-super`) | генерация JVM-класса в рантайме; класс создаёт ObjC-рантайм (`objc-reify`), одно-методный протокол — `reify` (§4); §10 называет разрешённым исключением, cljs его тоже не несёт |
| `bean` | отражение JavaBean'а в мапу через JVM-рефлексию; ObjC-аналог (KVC) — дело моста (§5), а не ядра; §10 называет разрешённым исключением |
| `gen-class`, `gen-interface`, `definterface` | объявление JVM-класса и интерфейса байткодом ради AOT; компилятор эмитит нативный код (§6), протокол — слоты дескриптора, а не интерфейс (§4); §10 называет разрешённым исключением |
| `class`, `class?`, `supers`, `bases`, `cast` | `Class` как значение с цепочкой суперклассов; host-тип здесь — значение, опознание — каст, а не имя (§4), и значение отдаёт `type` |
| Внутренности протоколов и multimethod'ов JVM (`extenders`, `find-protocol-impl`, `find-protocol-method`, `-cache-protocol-fn`, `-reset-methods`, `method-sig`, `primitives-classnames`) | множество расширителей не материализовано: метод протокола — слот дескриптора и inline cache в C (§4) |
| Флаги и имена JVM-компилятора и загрузчика классов (`compile`, `*compile-path*`, `*compile-files*`, `*compiler-options*`, `*warn-on-reflection*`, `*unchecked-math*`, `*allow-unresolved-vars*`, `*verbose-defrecords*`, `*fn-loader*`, `*use-context-classloader*`, `add-classpath`, `with-loading-context`, `namespace-munge`) | они называют `clojure.lang.Compiler`, classpath и загрузчик классов; компиляция здесь — отдельный шаг со своим кэшем (§6, §3 «Кэш»), стоимость и небезопасная арифметика — факты и явные двойники (§3), рефлексии нет вообще |
| Крючки JVM-ридера (`*read-eval*`, `*suppress-read*`, `*reader-resolver*`, `reader-conditional`, `reader-conditional?`, `load-reader`) | `#=` нет, так что `*read-eval*` нечего выключать; `#?` ридер раскрывает по нашему ключу, режима `:read-cond :preserve` нет; вход для текста — `load-string` |
| `unquote`/`unquote-splicing` как вары | заглушки, в которые JVM-ридер раскрывает `~`/`~@` вне syntax-quote; наш ридер собирает syntax-quote сам, и форма вне него — ошибка чтения, а не вызов вара |
| Внутренности JVM-принтера, выставленные варами (`print-dup`, `print-ctor`, `print-simple`, `PrintWriter-on`, `char-escape-string`, `char-name-string`, `StackTraceElement->vec`) | печать — C (`print_line`), таблицы экранирования и `java.io.Writer` варами не являются; точка расширения одна — `print-method` по `type` |
| Seq'и и редьюсы над JVM-типами (`enumeration-seq`, `iterator-seq`, `resultset-seq`, `xml-seq`, `stream-seq!`, `stream-reduce!`, `stream-into!`, `stream-transduce!`) | каждое называет тип JDK; источник здесь — `seq`/`reduce` по нашим значениям, ObjC-перечислитель приезжает через мост (§5) |
| Структуры (`defstruct`, `create-struct`, `struct`, `struct-map`, `accessor`) | вытеснены `defrecord` и схемами (§4); cljs их тоже не несёт |
| `definline` | инлайн — решение компилятора по фактам и бюджету (§3, §6b), а не второй экземпляр тела в варе |
| Конструкторы gvec'а JVM-ядра (`->Vec`, `->VecNode`, `->VecSeq`, `EMPTY-NODE`) | `deftype`'ы, которыми на JVM сделан `vector-of`; у нас это тип в C, его узлы варами не выставлены |
| Порядок `seq` маленькой мапы как у `PersistentArrayMap` (по вставке) | порядок `seq` хэш-мапы в Clojure не определён, и JVM-овский — следствие второго представления до восьми ключей; shape-мапа (§4 «Представление по наблюдению») хранит набор ключей, а не порядок вставки, и второе представление ради порядка — цена без гарантии (`docs/jvm-differences.md`) |
| Молчаливая обёртка двух дополнений там, где значения нет (`(Math/abs Long/MIN_VALUE)` → `Long/MIN_VALUE`, `(long ##NaN)` → `0`) | это не ответ, а его отсутствие, выданное за число: `abs` — `(if (neg? a) (- a) a)` над проверяемым вычитанием, и Swift на том же преобразовании тоже ловит. Громкая ошибка дешевле неверного числа, уехавшего в расчёт (`docs/jvm-differences.md`) |
| `java.lang`-поверхность боксовых классов целиком (`Float`, `*/TYPE`, конструкторы `Long.`/`Double.`, `Class/forName`) ради статиков вроде `Long/MAX_VALUE` | класс значением здесь не является (строка про `class`/`cast` выше), так что статик — вар в пространстве имён с именем класса, та же форма, что у `Thread/sleep`; набор растёт по спросу, по строке на имя, а не слепком чужого пакета (`docs/jvm-differences.md`) |
| Spawn locality: порождённая корутина не начинается, пока спавнер не дойдёт до ближайшего парка | Такого не обещает ни один хост с настоящими потоками. Замер на JVM-core.async 1.6.681: `go`-блок видит счётчик спавнера на 1, 70, 76, 106 и 1000 из 1000 инкрементов (у нас 0–15 из 1000), то есть первый шаг там начинается, пока спавнер ещё работает, и порядок — следствие задержки dispatch-очереди в десятки микросекунд, а не гарантии; на миллионе инкрементов JVM стартует на 600–4000-м. Цена же локальности — fan-out: `(dotimes [_ 8] (go …))` из исполнения, которое не паркуется никогда (обработчик кнопки возвращается в run loop), не начал бы ни одной корутины, а «не начинать» пришлось бы держать через состояние чужого исполнения — инвариант пробуждения «ни одна готовая корутина не лежит в очереди, пока все носители спят» (NOTES «Scheduler») стал бы условным, и носитель, заблокированный под `host_depth`, держал бы своих детей. Покупается при этом только порядок первого шага: всё, что сложнее, остаётся гонкой. Единственное расхождение, которое это закрыло бы, — блок ASYNC-127 в `async_test.clj`, где `mult` над заполненным буфером успевает слить его до `tap`, и сам `mult` документирует «Items received when there are no taps get dropped» (`docs/jvm-differences.md`) |
| `Thread/currentThread` и идентичность потока как значение | Единица исполнения здесь — корутина, и она меняет носитель на каждом парке, так что отданный наружу идентификатор потока отвечает не на тот вопрос и годится как ключ ровно до первого `<!`; у `Thread` здесь нет ни одного метода, а `Thread/sleep` — глагол с полным смыслом (парк на таймерном потоке), не идентичность. Два `deftest` core.async, чей предмет — на каком потоке бежит колбэк `put!`/`take!`, не грузятся целиком, и это честнее заглушки, которая отвечала бы адресом носителя (`docs/jvm-differences.md`) |
| Позиция ридера (`:line`/`:column`) у цитированного списка в скомпилированной константе | метаданные константы в её печатной форме не едут, и пул восстанавливает их обёрткой; ридер вешает позицию на каждый прочитанный список, так что обёртка на каждый стоила бы пулу по мапе на список ради сведений, которыми скомпилированный юнит не пользуется — остальные метаданные цитированной формы сохраняются в обоих бэкендах (NOTES «Compiler») |
