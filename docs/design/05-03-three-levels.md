### Три уровня, одновременно
1. **ObjC-рантайм** — всё `@objc` (UIKit, Foundation, AVFoundation…), из REPL, без пересборки. ~70% реального приложения.
2. **Генерируемый мост для Swift-only** — стабы печатаются на сборке из symbol graph, а не пишутся руками; см. «Генератор стабов» ниже. «Подключил SwiftUI — получил всё» не выйдет и с генератором: часть поверхности не зовётся динамически в принципе (result builders, макросы) — но это записанный список, а не сюрприз.
3. **Данные через границу** — Clojure отдаёт описание, Swift исполняет. Для SwiftUI это не компромисс, а архитектура: view-дерево как данные, Swift-рендерер с фиксированным набором компонентов. Elm/re-frame.

Под всеми тремя — C (§5 «C — уровень 0»): вызывается динамически, как ObjC, и единственный из мостов полезен на любой платформе.

**Редкость — довод за генератор, а не против (решено 2026-09-27).** Уровень 2 строится. Прямые Swift-вызовы ожидаются *редкими*, и редкость делает генератор дешёвым, а не ненужным: короткий список символов — это быстрый swiftc и маленькая таблица регистрации, то есть снятый страх «жадная генерация кладёт swiftc» из «Генератора стабов» ниже. Альтернатива — рукописные стабы — дешева для *нас* и постоянный налог на *каждого* прикладного разработчика: владение и конвенции выводятся заново на каждом вызове. Но редкость **поднимает** ставку на символ, и это надо записать: редкое не значит предсказуемое — своя дюжина нужна каждому приложению, — поэтому требование общности с генератора не снимается, снимается только объём. И арифметика хвоста переворачивается: на 500 символах «90 % перепечатывается чисто» — хорошо, на двенадцати не перепечатавшийся один и есть тот, который нужен, и объехать его нечем.

Граница: Clojure — «мозг» (состояние, логика, данные, сеть), Swift — «руки» (рендер, hot paths, Metal). Переход стоит десятки нс: ноль для UI-событий, приговор для пиксельного цикла.

Реальная потеря без eval Swift: нельзя из REPL исследовать Swift-only API, которого нет в мосту.
