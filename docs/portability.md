# Portability ledger

Other platforms are the last goal of the project, after everything else (design §10). Until then the
runtime is built and tested on Apple platforms only, and this page is the one place that records every
spot where the code assumes them, so that the port is a walk down a list rather than an archaeology.

Two rules keep the list complete:

- **Behaviour is one; only the mechanism is per platform.** A platform-specific branch may choose how
  to find a stack bound, a section, a register or a random byte; it may not change what a program
  observes. A branch whose other side is "not supported" is a listed gap, not a design.
- **`make port-audit` fails on an unlisted spot.** The script greps the sources for the platform markers
  below and compares the files it finds against this ledger. A new Apple-only API in a file that is not
  listed here fails the audit; add the row. Agents: every task that adds such a spot adds its row.

## Spots

| file | what is Apple-specific | fallback today | port note |
|---|---|---|---|
| `include/clj/lock.h` | `os_unfair_lock` | `pthread_mutex_t` on other platforms | Semantics identical; the mutex is 2× slower (bench). |
| `shadow.c`, `eval.c` (stack limit) | `pthread_get_stackaddr_np` for the thread's stack bounds | a fixed 512 KB assumption from the first call | `pthread_getattr_np` on Linux gives the same. |
| `guard.c`, `guard_internal.h` | guard-page overflow recovery: `sigaltstack`, `ucontext` register layout for arm64/x86_64 macOS; `CLJ_CRASH_EXIT` skips the crash reporter's corpse path (ReportCrash answering `EXC_CRASH`) | none — a compiled overflow is a plain crash elsewhere | Same design on Linux with its `ucontext` field names; the interpreter's own check is portable; the `_exit` fallback is plain POSIX and matters only where a crash reporter can wedge the death. |
| `trace.c` | frame and site tables found through `getsectiondata` in Mach-O sections `__TEXT,__cljframe`/`__cljsite`; PAC stripping on arm64e | none — traces carry no compiled frames elsewhere | ELF: same sections with `__start_`/`__stop_` symbols; PAC is arm64e-only anyway. |
| `compiled_internal.h` | the frame attributes (`section(...)`) and the site-marker emission the compiler relies on | none | Section names follow the object format; the attribute spelling differs between Mach-O and ELF. |

| `coro.c` | the context switch in asm for arm64 and x86_64 (Darwin symbol prefix `_`); `mmap`/`mprotect` for the stack reserve and its guard page; `MADV_FREE_REUSABLE` for a parked stack's tail and for an evacuated mapping, `MADV_FREE_REUSE` before a restore re-dirties it (footprint accounting); `task_info(TASK_VM_INFO)` for the physical footprint; `DISPATCH_SOURCE_TYPE_MEMORYPRESSURE` as the evacuate-everything trigger; the ASan fiber hooks | the sweep alone evacuates elsewhere; no pressure trigger | Linux: the same asm without the underscore, `MADV_DONTNEED` (no REUSE step: the pages are dropped, not lazily reclaimed), `/proc/self/statm`, a cgroup `memory.events`/`memory.pressure` (PSI) watcher for the pressure trigger; the fiber hooks are the sanitizer's, not the OS's. |
| `sched.c` | `pthread_set_qos_class_self_np` on the carriers; the main carrier is a version-0 `CFRunLoopSource` signalled with `CFRunLoopWakeUp`; a far timer deadline is kept on a `DISPATCH_SOURCE_TYPE_TIMER` so the timer thread waits untimed (a timed wait wakes ~0.7 µs later on XNU); the remaining timed waits (`cond_wait_ns`) use `pthread_cond_timedwait_relative_np`, which needs no clock read | the main carrier queue alone (a host can pump it by hand); `cond_wait_ns` falls back to a `pthread_cond_timedwait` on a `CLOCK_REALTIME` deadline, and every deadline takes it | Linux: an `eventfd` in the host's `epoll`/GLib loop performs the same pump; QoS has no equivalent; measure whether futex timed waits carry the same wake penalty before porting the dispatch timer (a `timerfd` in the same thread's `poll` if they do). Every deadline then waits on the condition, so its clock must be monotonic — `pthread_condattr_setclock(CLOCK_MONOTONIC)` or the `timerfd`, never the `CLOCK_REALTIME` deadline of the non-Apple `cond_wait_ns` branch; and the clock matching Darwin's `CLOCK_UPTIME_RAW` (stopped while the device sleeps, the semantics of NOTES.md "The timers' clock") is Linux's `CLOCK_MONOTONIC`, not `CLOCK_BOOTTIME`. |
| `objc.c`, `include/clj/objc.h`, `coro.c` (the pool drain) | the whole level-1 bridge: the Objective-C runtime (`objc_getClass`, `class_copyMethodList`, `method_copyArgumentType`), `objc_msgSend` through hand-written prototypes chosen by the type encoding, the AAPCS64 classification of a struct argument or return, the ARC entry points `objc_retain`/`objc_release`/`objc_autorelease`/`objc_autoreleasePoolPush`/`Pop`, `NSString`/`NSNumber`/`NSNull`/`NSArray`/`NSDictionary` and the `kCFBoolean*` singletons, the `__x86_64__` reading of a `c` return as a BOOL, the `__x86_64__` refusal of every struct shape SysV classifies differently from arm64; and, for calling in, `objc_allocateClassPair`/`class_addMethod`/`class_addProtocol`/`objc_registerClassPair`/`class_createInstance`/`object_getIndexedIvars`/`objc_msgSendSuper`, `protocol_copyMethodDescriptionList`, and the libclosure block ABI (`_NSConcreteStackBlock`, `_Block_copy`, the flag bits and descriptor tail of the non-public `Block_private.h`) | none — every entry point answers "The Objective-C bridge needs an Apple platform" | A listed gap, not a design: the bridge exists to call Apple frameworks. The kebab spelling and the analyzer's `.method` form are plain C and portable; a port would put a different host's dispatcher behind the same node. The prototypes are an arm64/x86_64 fact (separate integer and floating-point register files, unread extra argument registers), so another ABI re-derives the set, and the trampolines that call in are the same set read backwards — the IMP and block-invoke prototypes are the send ones with `self`/`_cmd` or the block in place of the receiver, and calling a block the host handed us is the send side reading that identity backwards — its first argument rides in the register a method's `_cmd` uses. `BOOL` is `B` (C `bool`) on arm64 and a signed `char` on x86_64, so the encoding a pointer argument carries for `objc-write!` differs between them and the fixture's block signatures are written for arm64. Struct passing is arm64's AAPCS64: an HFA of up to four same-typed floats or doubles in v0-v3, any other aggregate of at most 16 bytes in integer registers, a larger one by a pointer and through x8 for a return, whose callee-side shape is one char array per size (4-byte steps: a struct's size is a multiple of its widest member's alignment) because an indirect return's ABI reads the size and nothing else. On x86_64 SysV classifies by eightbyte instead ({float,float} share one xmm, an aggregate over 16 bytes rides the stack and its return needs `objc_msgSend_stret`, which arm64 does not have), so only all-integer aggregates of at most 16 bytes and one or two `double`s are accepted there and every other struct is refused rather than called through a wrong shape, which leaves x86_64 with no callback returning one through x8 either. GNUstep's libobjc2 has the same class-pair and block entry points, so a port re-points them rather than re-designing. |
| `cmutex.c`, `chan.c`, `runtime.c` (the writer thread) | pthreads and C atomics only | — | Portable; listed so the audit knows the scheduler files were read. |
| `Sources/CljNREPL/Socket.swift` | `sockaddr_in.sin_len`, which only Darwin's struct has | `#if canImport(Darwin)` skips the field elsewhere | Portable POSIX sockets otherwise (`#if canImport(Darwin) import Darwin #else import Glibc #endif`); not caught by `port-audit`'s markers, listed anyway. |

## Not platform-specific, worth knowing

- The interpreter, the analyzer, the facts pass, the compiler's generator and every collection are plain
  C17 and Swift with no platform calls; `boot/core.c` is generated and carries whatever
  `compiled_internal.h` carries.
- The deadline, the shadow stack, the atoms, the pool allocator use only pthreads and C atomics.
- The coroutine mutex, the parking lot, the channels and the output writer are pthreads and C atomics; only the
  switch, the stack mapping and the main carrier's run-loop source are platform code (rows above).
- A coroutine may resume on another thread, so no `_Thread_local` is read through an address cached across a
  call that can park (NOTES.md "Coroutines", TLS); that rule is the same on every platform.
