# Clojure для Apple-платформ — дизайн-заметки

Итог обсуждения. Стартовый вопрос был «Clojure поверх Swift как ClojureDart поверх Dart»; по ходу выяснилось, что правильная позиция — **Clojure на Apple-рантайме**: своё ядро на C, хост-интероп со Swift/ObjC через мост, а не транспиляция в Swift.

---

Документ разбит на файлы в [`docs/design/`](design/): по файлу на раздел, а большие §3, §4 и §5 — по файлу на подраздел. Номера § и заголовки подразделов прежние, поэтому ссылка вида «design §4 «Атомы»» находится здесь по номеру и заголовку. Читать оглавление, открывать только нужный файл.

Состояние помечено в самом тексте: `[x]` сделано, `[~]` сделано частично (что осталось — названо в пункте), `[ ]` открыто. Так размечены шаги §10 (статус шага — абзацем или подпунктом под ним), вопросы §9 и порядок работ интерпретатора в §6b. Открытое из обоих документов сведено в [`docs/open.md`](open.md): его пишет `make open-items` из пометок, `make open-items-audit` падает, если он отстал.

## Оглавление

- **§1. Почему Swift плохой хост «в лоб»** — [01-why-not-swift.md](design/01-why-not-swift.md): нет eval/JIT и рефлексии вызовов, ARC, медленный swiftc, strict concurrency; ObjC-рантайм — то, что остаётся динамическим.
- **§2. Три смысла слова «хост» и итоговый выбор** — [02-host-choice.md](design/02-host-choice.md): компиляция в C, рантайм — C-ядро со Swift-обвязкой, интероп — Swift и ObjC; модель Clojure JVM, а не ClojureDart.
- **§3. Архитектура**
  - «Слои» — [03-01-layers.md](design/03-01-layers.md): Clojure-код, мост (Swift/ObjC), портируемое C-ядро; ничего платформенного в ядре.
  - «Два режима исполнения» — [03-02-execution-modes.md](design/03-02-execution-modes.md): dev — скомпилированная база плюс интерпретируемые дельты, прод — только C.
  - «Пайплайн» — [03-03-pipeline.md](design/03-03-pipeline.md): reader → macroexpand → analyzer → общий optimizer → backend {closures | C}.
  - «Аналитор как библиотека: где живёт анализ» — [03-04-analyzer-as-library.md](design/03-04-analyzer-as-library.md): вывод в общем аналиторе с тремя клиентами, а не в компиляторе и не в отдельном анализаторе.
  - «Покрытие вывода типов: три слоя» — [03-05-inference-coverage.md](design/03-05-inference-coverage.md): статика, предсказуемость в рантайме, схема на границе; метрика покрытия.
  - «Вывод фактов: решётка, два прохода, уточнения» — [03-06-facts.md](design/03-06-facts.md): абстрактная интерпретация над решёткой фактов, схема денотирует факт, строгость, пределы и скорость.
  - «Диагностика: ошибка объясняет, а не констатирует» — [03-07-diagnostics.md](design/03-07-diagnostics.md): исправление выводится из текста ошибки — для человека и для агента; ошибки везде, линтинг — только на формах пользователя (оригинальность по идентичности).
  - «Tagged-vector DSL: hiccup и данные с диспатчем по голове» — [03-08-tagged-vector-dsl.md](design/03-08-tagged-vector-dsl.md): тег проверяется схемой-якорем `[:ref ::view]` с `:multi` по голове, без нового слова языка; литерал с известным тегом строится напрямую.
  - «Инвариант: язык не меняется» — [03-09-language-invariant.md](design/03-09-language-invariant.md): валидная Clojure-программа валидна здесь с тем же результатом; факты меняют только стоимость и диагностику.
  - «Dev client (паттерн Expo)» — [03-10-dev-client.md](design/03-10-dev-client.md): dev-сборка — ядро, интерпретатор и мосты; пересборка шелла только на новую Swift-зависимость.
  - «Явные двойники неявных оптимизаций» — [03-11-explicit-twins.md](design/03-11-explicit-twins.md): явная форма — тот же механизм с гарантией, двойник только по имени — дефект; лестница «код → утверждение → двойник».
  - «Кэш: общее хранилище по содержимому, тонкий каталог в проекте» — [03-12-cache.md](design/03-12-cache.md): зависимости и Swift-стабы — в общем хранилище по ключу Меркла с самоочисткой, свой код и закрытый мир — в проекте; core поставляется с тулчейном.
  - «Корректность реализации: баг языка находит машина, а не пользователь» — [03-13-implementation-correctness.md](design/03-13-implementation-correctness.md): сгенерированные входы против оракулов (JVM, интерпретатор, модель), сравнение исхода, а не текста; внутренняя ошибка громкая, рубильник оптимизаций.
- **§4. Рантайм**
  - «Представление значений» — [04-01-values.md](design/04-01-values.md): свой заголовок, теговые указатели и аллокатор вместо Swift-классов.
  - «Var и ленивые def» — [04-02-vars-and-lazy-def.md](design/04-02-vars-and-lazy-def.md): чистые `def` ленивы через thunk в корне вара, эффектные — eager.
  - «Порядок объявлений (hoisting)» — [04-03-hoisting.md](design/04-03-hoisting.md): порядок как в Clojure плюс диагностика «определён ниже»; pre-pass отвергнут; фазы выведены, а не объявлены; отложенный анализ тел — кандидат по триггеру.
  - «Персистентные структуры — где деньги» — [04-04-persistent-structures.md](design/04-04-persistent-structures.md): стоимость копии HAMT-узла, неатомарный RC, reuse, регионы.
  - «Представление по наблюдению: shapes, tuples, elements kinds» — [04-05-shapes.md](design/04-05-shapes.md): keyword-мапы как shapes, кортежи, виды элементов вектора (V8).
  - «Низкоуровневый слой: числа, layout, память» — [04-06-low-level-layer.md](design/04-06-low-level-layer.md): `deflayout`, чужая память как view, владение, числовая башня.
  - «Атомы» — [04-07-atoms.md](design/04-07-atoms.md): атом в C-ядре: `f` ровно раз под корутинным мьютексом, `deref` без лока, вложенный `swap!` — trap, трюк уникальности снят.
  - «Подписки (вместо Observable-макроса)» — [04-08-subscriptions.md](design/04-08-subscriptions.md): `add-watch` на атом, пути — слой курсоров выше.
  - «Функции» — [04-09-functions.md](design/04-09-functions.md): Clojure-fn не Swift-замыкание; скомпилированная fn — таблица арностей.
  - «Протоколы и типы — свои, в обоих режимах» — [04-10-protocols-and-types.md](design/04-10-protocols-and-types.md): своя таблица диспатча, не хостовые типы.
  - «Дескриптор типа: core-интерфейсы как слоты» — [04-11-type-descriptor.md](design/04-11-type-descriptor.md): дескриптор со слотами (как `tp_*` CPython), write-once core-слоты.
  - «Роли конструкций и ссылочные типы» — [04-12-construct-roles.md](design/04-12-construct-roles.md): `defrecord`/`deftype`/`reify`/`deflayout`, мутабельные поля, atom/agent/ref.
  - «Мультиметоды» — [04-13-multimethods.md](design/04-13-multimethods.md): целиком в рантайме; хост только в `isa?` на хостовых типах.
  - «core.async» — [04-14-core-async.md](design/04-14-core-async.md): `go` на stackful-корутинах в обоих режимах, свои каналы, affinity, отмена, стеки и эвакуация припаркованных.
  - «Ошибки и стектрейсы» — [04-15-errors-and-traces.md](design/04-15-errors-and-traces.md): `#line` и DWARF в компиляторе, теневой стек в интерпретаторе.
  - «Тип ошибки, `catch` по кейворду, отмена» — [04-16-error-type-catch-cancel.md](design/04-16-error-type-catch-cancel.md): бросается любое значение, `ex-type`, хостовая ошибка по типу, `:cancelled` не `ex-info`.
  - «Агенты и ref'ы» — [04-17-agents-and-refs.md](design/04-17-agents-and-refs.md): агент — очередь действий в атоме, `send` на носителях, `send-off` на пуле блокирующих задач, действие не наследует привязок и дедлайна запустившего; ref — 2PL по id: ожидание лока только по возрастанию id, иначе ретрай, `commute` под тем же локом, истории нет.
- **§5. Интероп**
  - «Главное разделение: данные vs вызовы» — [05-01-data-vs-calls.md](design/05-01-data-vs-calls.md): Swift-рантайм отдаёт данные динамически, вызовы — нет.
  - «Что умеет Swift-рантайм (wickwirew/Runtime, Echo и ниже)» — [05-02-swift-runtime.md](design/05-02-swift-runtime.md): что можно и чего нельзя сделать с метаданными.
  - «Три уровня, одновременно» — [05-03-three-levels.md](design/05-03-three-levels.md): ObjC-рантайм, генерируемый мост для Swift-only, данные через границу; редкость — довод за генератор.
  - «Как пишется вызов» — [05-04-call-syntax.md](design/05-04-call-syntax.md): базовое имя плюс метки-кейворды в порядке селектора.
  - «Что конвертируется само, а что рукой» — [05-05-conversion.md](design/05-05-conversion.md): скаляры неявно, коллекции явно.
  - «Вызов внутрь: делегат не паркуется» — [05-06-calling-in.md](design/05-06-calling-in.md): тело `reify` на `@objc` и блока исполняется под `host_depth`.
  - «Генератор стабов» — [05-07-stub-generator.md](design/05-07-stub-generator.md): symbol graph на входе, перепечатка типов, боксы и их равенство, дженерики, отчёт, тихие риски, запасной выход.
  - «`mutating`, `inout`, `borrowing`, `consuming`» — [05-08-mutating-inout.md](design/05-08-mutating-inout.md): одно правило для `inout`, включая `self`.
  - «`throws` — четыре формы» — [05-09-throws.md](design/05-09-throws.md): конкретный `throws(E)`, `any Error`, `Never` и `rethrows` — что стаб делает с каждой.
  - «Объявленная граница, REPL, доставка стабов» — [05-10-declared-boundary.md](design/05-10-declared-boundary.md): `:host-call` как факт, `require-swift` в `ns`.
  - «Swift → Clojure» — [05-11-swift-to-clojure.md](design/05-11-swift-to-clojure.md): `Value` — один тип на границе, вызов Clojure из Swift.
  - «Замыкания через границу: цвет живёт в Swift» — [05-12-closures.md](design/05-12-closures.md): async-адаптация по Swift-сигнатуре, `@MainActor` как affinity, цена изоляции.
  - «ABI» — [05-13-abi.md](design/05-13-abi.md): C ABI между сгенерированным C, ядром и Swift-частью.
  - «C — уровень 0» — [05-14-c.md](design/05-14-c.md): C зовётся динамически — диспетчер уровня 1 на любой указатель; декларации и константы из заголовка clang'ом, не Swift-импортом; единственный мост, полезный на любой платформе.
- **§5b. UI-слой** — [05b-ui.md](design/05b-ui.md): язык не знает про UI; реконсилер, бэкенды, Yoga, через границу идут изменения; `:key` как идентичность строки, размещение ребёнка — вызов бэкенда; идентичность узла — слот, компонент и действие — `[#'f args]`, локальное состояние — атом узла по `:ui/local`, обёртка по условию сохраняет базу, `:key` сопоставляется по проходу, модификатор — лэйаут-обёртка со стандартными атрибутами как сахаром, грамматика — надмножество Reagent, `defui` с директивами и схемой, коллекция — `:items`/`:item` над ленивым лэйаутом с viewport, горячие значения — привязки мимо реконсилера.
- **§5c. Инструментарий: nREPL, LSP** — [05c-tooling.md](design/05c-tooling.md): встраивание протоколами; nREPL сразу; один свой LSP на месте clojure-lsp, сразу финальный.
- **§6. Компилятор** — [06-compiler.md](design/06-compiler.md): закрытый мир, оптимизации по источнику права, нет JIT и есть PGO, инлайнинг, бэкенд — C через clang.
